# OpenHarmony Build (ohos-project)

This directory is a standard DevEco Studio / Hvigor project for
**OpenHarmony 5.0 (API 12)**. It wraps the repository's Kirikiri SDL2 engine
and the complete game content into an installable .hap package.

## Layout

- AppScope/ - application-level manifest (bundle name, version, icon).
- entry/ - the only module:
  - src/main/ets/ - ArkTS shell: EntryAbility plus the Index page that hosts
    the game's XComponent.
  - src/main/cpp/ - native code:
    - napi_init.cpp - the entry NAPI module.
    - krkrsdl2_ohos_entry.cpp - XComponent surface/touch state and the
      Kirikiri engine thread.
    - ohos_data_extract.cpp - first-launch extraction of rawfile game data
      into the application sandbox.
    - sdl_ohos/ - the OpenHarmony SDL2 backend (video driver over
      XComponent + EGL, event glue, filesystem hooks).
    - third_party/SDL - vendored SDL2 with the backend patch applied. This
      directory is generated by tools/setup_ohos_project.py and is not
      committed.
  - src/main/resources/ - strings, colors, icons, page profiles and the
    packaged rawfile game content.
- build-profile.json5, hvigorfile.ts, oh-package.json5,
  hvigor/hvigor-config.json5 - Hvigor build configuration (model version
  5.0.0, compatible SDK 5.0.0(12), runtimeOS OpenHarmony).

## How the build works

The Hvigor build compiles entry/src/main/cpp with the OpenHarmony NDK
CMake toolchain. The entry CMakeLists.txt:

1. builds the vendored, patched SDL2 as a static library,
2. adds the repository root CMake project, which produces the shared
   krkrsdl2 engine library (see the OHOS branch in the root CMakeLists.txt),
3. links everything into libentry.so together with the OpenHarmony native
   libraries (ace_ndk, native_window, rawfile, hilog).

At runtime the Index page hands its XComponent to the native side, the
engine thread waits for the surface, extracts the game data and runs the
Kirikiri engine. Rendering uses EGL/GLES through the XComponent surface;
touch input is translated into SDL mouse events.

### Game content

Game assets are not duplicated in the repository. The packaging step reads
entry/src/main/resources/rawfile/data, which tools/setup_ohos_project.py
exposes as a junction/symlink to the repository root data/ directory. The
GitHub Actions workflow runs that script automatically. On first launch the
app extracts the rawfile content into the sandbox files directory
(filesDir/data) and skips that work on later launches by comparing the
packaged content-manifest.json hash.

## Local builds

Prerequisites:

- Git submodules and LFS content (git submodule update --init, git lfs pull).
- DevEco Studio 5.0.0 for OpenHarmony (API 12), or the OpenHarmony 5.0.0
  command line tools + SDK with DEVECO_SDK_HOME set.
- Python 3 (for the setup script).

Prepare the project:

    python tools/setup_ohos_project.py

Then either open this directory in DevEco Studio and run the entry module,
or build from the command line:

    hvigorw assembleHap --mode module -p product=default -p buildMode=release --no-daemon

The output HAP appears under entry/build/default/outputs/default/ (signed
when DevEco signing is configured, otherwise entry-default-unsigned.hap).

## Signing

The workflow builds an unsigned HAP and its signing is controlled by the
`sign_mode` workflow input (default `community`):

- `none` - no signing. The release asset is the unsigned HAP;
  install it only after signing it with your own materials.
- `community` (default) - signs with the community OpenHarmony debug certificate
  (the official developtools_hapsigner autosign flow). The result installs
  directly on OpenHarmony devices that have developer mode enabled, but
  HarmonyOS 5+ (NEXT) devices reject this certificate.
- `agc` - signs with your own AppGallery Connect materials provided as
  the six repository secrets below. This is the mode that produces a HAP
  which installs on HarmonyOS 5.0 and later (and on OpenHarmony):

  - OHOS_KEYSTORE_P12_BASE64
  - OHOS_KEYSTORE_PASSWORD
  - OHOS_KEY_ALIAS
  - OHOS_KEY_PASSWORD
  - OHOS_APP_CERT_BASE64 (the .cer application certificate)
  - OHOS_PROFILE_P7B_BASE64 (the .p7b provisioning profile)

Tag pushes default to `community` unless the repository variable
`OHOS_DEFAULT_SIGN_MODE` is set; re-run the workflow manually on the same
tag with the desired mode to replace the release assets.

The workflow signs with hapsigntoolv2.jar from the Huawei mirror
(SHA256withECDSA, local signing).

### Signing the downloaded HAP locally

If you prefer to sign on your own machine (Windows), run
`tools/sign_hap_agc.ps1`. DevEco Studio 5 installs everything the script
needs (Java + hap-sign-tool); it auto-detects both:

    powershell -ExecutionPolicy Bypass -File tools\sign_hap_agc.ps1 ^
      -Hap Yosuga-...-unsigned.hap ^
      -Keystore app.p12 -KeystorePassword ******** ^
      -KeyAlias mykey -KeyPassword ******** ^
      -AppCert app.cer -Profile profile.p7b

Then install the signed HAP with `hdc install <signed.hap>`.

### Getting AGC materials for HarmonyOS 5+

1. Register an app in AppGallery Connect. Its bundle name must be
   `com.lightwinder.yosuganosora.hdremake` (the name baked into
   AppScope/app.json5). If you register a different name, change
   AppScope/app.json5 and rebuild.
2. Create the keystore (.p12) and download the application certificate
   (.cer) issued for it.
3. Create a release provisioning profile (发布 Profile) for the app and
   download it (.p7b).
4. Either configure the six secrets and run the workflow with
   sign_mode=agc, or sign locally with `tools/sign_hap_agc.ps1`.

HarmonyOS NEXT only accepts AGC-issued certificates and profiles, so the
same HAP serves both OpenHarmony (community or AGC signing) and HarmonyOS
NEXT (AGC signing).

## Current limitations

- Audio: SDL2 has no audio backend on OpenHarmony yet; the engine runs with
  SDL's dummy audio driver (no sound). A future OHAudio backend would plug
  in here.
- Movies: video playback uses the portable SDL2 path rather than a hardware
  decoder overlay.
- Text input: no soft keyboard integration for script text fields.
- First launch: the 3+ GiB game data extraction takes a while and
  temporarily needs roughly twice the game size on disk.

## CI

.github/workflows/release-ohos.yml builds the HAP on ubuntu-24.04:
downloads the OpenHarmony 5.0.0 SDK and command line tools, runs the
project setup, assembles the release HAP, optionally signs it, verifies the
package contents and publishes multipart 7-Zip volumes to the GitHub
Release. The SDK download URLs can be overridden with the repository
variables OHOS_SDK_URL and OHOS_COMMAND_LINE_TOOLS_URL when the
OpenHarmony release page publishes newer packages.
